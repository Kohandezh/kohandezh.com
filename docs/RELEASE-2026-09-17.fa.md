## ۱) خلاصهٔ کارهای این نشست

### الف) مرحلهٔ ۱ — تشخیص ElevenLabs Crawl
- **وضعیت: انجام‌شده با محدودیت** — علت قطعی بدون خطای job مالک «نامشخص» است.
- شواهد سمت سایت همگی سبز (بررسی خواندنی production):
  - `robots.txt` واقعی: فقط `Allow`، هیچ `Disallow` وجود ندارد → ElevenLabs بلاک نبود.
  - صفحهٔ اصلی با UA `ElevenlabsBot/1.0`: HTTP 200، text/html، ۲۱۱٬۶۴۰ بایت، بدون redirect، `x-litespeed-cache: hit`؛ ۳ درخواست متوالی همه ۲۰۰.
  - محتوای HTML خام بدون JS کامل است (۴۶× نام Kohandezh، ۲۰× KSF، ۹× نقش timeline) → استخراج ممکن.
  - `sitemap.xml`: 200 application/xml. `http://` و `www` بدون مشکل به canonical می‌رسند.
  - `.htaccess`: هیچ قانون ضدربات یا بلاک UA ندارد؛ CSP مانع خزندهٔ سمت‌سرور نیست.
- حقایق مستندات رسمی (elevenlabs.io، بازیابی ۲۰۲۶-۰۹-۱۷):
  - UA خزنده: `ElevenlabsBot/1.0`؛ به robots پایبند است؛ صفحهٔ مسدود = «سند ساخته‌شده ولی بدون محتوا».
  - سند باید به Agent متصل شود (`knowledge_base` در تنظیمات Agent / تب Dependent agents) — رایج‌ترین علت «استفاده نمی‌شود».
  - Crawl job: `max_depth` پیش‌فرض ۳ (۱-۵)، `max_pages` پیش‌فرض ۱۰۰۰، `pattern` اختیاری، `sitemap_urls` اختیاری (کشف خودکار را override می‌کند).
- **اصلاح محلی انجام‌شده:** بخش صریح `User-agent: ElevenlabsBot / Allow: /` به هر دو `robots.txt` و فیلتر `robots_txt` در functions.php اضافه شد (توصیهٔ رسمی مستندات؛ برای بقیهٔ ربات‌ها بی‌اثر). CLAUDE.md: ۱۵→۱۶ ربات. آینهٔ `_tooling/wp-root/robots.txt` توسط release prepare خودکار تازه شد.
- **پشتیبان پیش از تغییر:** `_tooling/backups/kdcv-stage1-elevenlabs-backup.tar.gz` (robots.txt + functions.php).
- **۴ دادهٔ لازم از مالک برای تشخیص قطعی:** متن/اسکرین‌شات خطا، URL واردشده، زمان تلاش، نوع import (Single URL / Website Crawl / Sitemap). بررسی لاگ LiteSpeed برای 403/429/5xx/timeout از UA مذکور (سمت مالک).
- فرضیهٔ باز: دسترسی شبکهٔ واقعی IPهای ElevenLabs به هاست ایران از بیرون قابل اثبات نیست.

### ب) زبان پیش‌فرض فارسی (درخواست مالک)
- **از قبل پیاده‌سازی بوده و راستی‌آزمایی شد — تغییر جدید لازم نداشت:**
  - `assets/js/locale-router.js:34` → `DEFAULT_LOCALE = "fa"` (بازدیدکنندهٔ بدون سیگنال → فارسی).
  - functions.php:632 → روتر جغرافیایی بعد از چک ربات، بدون‌سیگنال را به `/fa/` ریدایرکت می‌کند.
  - مرورگر واقعاً انگلیسی روی انگلیسی می‌ماند؛ ربات‌ها canonical انگلیسی `/` را ایندکس می‌کنند (قرارداد #۵ CLAUDE.md).
- اگر مالک بخواهد حتی مرورگر انگلیسی هم بار اول فارسی ببیند: تغییر کوچک است ولی ترافیک انگلیسی و canonical را عوض می‌کند — فقط با OK صریح.

- فقط frontend؛ wp-admin همیشه آزاد. اسکریپت inline یک‌خطی (preventDefault روی contextmenu) در فوتر.

- **تست واقعی روی وردپرس محلی (localhost:8888):** فعال‌سازی با wp-cli ✓؛ ON → اسکریپت در `/` و `/fa/` حاضر ✓؛ option=0 → صفر مورد ✓؛ برگشت → حاضر ✓؛ رندر صفحهٔ تنظیمات با کاربر ادمین RENDER_OK (۱۵۱۹ بایت) ✓؛ debug.log بدون خطای جدید ✓. محدودیت: کلیک راست با مرورگر واقعی توسط عامل کلیک نشده — رفتار استاندارد preventDefault است.
- نکتهٔ production: پس از تغییر کلید، کش LiteSpeed باید پاک شود وگرنه صفحات کش‌شده رفتار قدیمی را نشان می‌دهند.

## ۴) دستورالعمل اعمال روی هاست (به‌ترتیب؛ توسط مالک)

### فاز ۰ — پشتیبان‌گیری روی هاست (الزامی، قبل از هر replace)
1. از فایل‌منیجر هاست/FTP یک ZIP از `wp-content/themes/kohandezhcv/` بگیرید و دانلود کنید.
2. از `wp-content/plugins/` حداقل پوشه‌های `kohan-avatar` و `kohandezh-ai-hub` را ZIP بزنید و دانلود کنید.
3. ۱۶ فایل ریشهٔ فعلی کنار `wp-config.php` را دانلود کنید: `robots.txt، sitemap.xml، feed.xml، sw.js، manifest.json، offline.html` و ۱۰ فایل `llms.txt` (این‌ها نسخهٔ rollback ریشه‌اند).
4. (اختیاری) wp-admin → Tools → Export برای بکاپ محتوای XML.

### فاز ۱ — قالب
wp-admin → Appearance → Themes → Add New → Upload Theme → `kohandezhcv.zip` → **Replace active with uploaded**.

### فاز ۲ — افزونه‌ها (هر دو)
1. Plugins → Add New → Upload → `kohan-avatar.zip` → **Replace active with uploaded** (فعال می‌ماند).
2. Plugins → Add New → Upload → `kdcv-rightclick-guard.zip` → Install → **Activate**.
3. Settings → Right-Click Guard → ON یا OFF را انتخاب کنید (پیش‌فرض ON = راست‌کلیک برای بازدیدکننده بسته).

### فاز ۳ — فایل‌های ریشه
محتوای `root-files.zip` را extract و هر ۱۶ فایل را در **ریشهٔ وب هاست (کنار wp-config.php)** آپلود و replace کنید.

### فاز ۴ — پاک‌سازی کش
wp-admin → LiteSpeed Cache → **Purge All** (و در صورت وجود، کش CDN). بدون این مرحله صفحات کش‌شده قدیمی می‌مانند (شامل رفتار راست‌کلیک).

### فاز ۵ — مهاجرت‌های خودکار
یک بار هر صفحهٔ wp-admin را باز کنید؛ `kdcv_content_schema_version` مهاجرت‌ها (ساخت صفحات، flush ریرایت) را خودکار انجام می‌دهد. اگر ۴۰۴ دیدید: Settings → Permalinks → Save یک بار.

## ۵) Rollback
1. قالب: آپلود همان ZIP پشتیبان فاز ۰ از طریق همان مسیر Upload → Replace active.
2. افزونه‌ها: غیرفعال/حذف `kdcv-rightclick-guard`؛ برای kohan-avatar آپلود نسخهٔ پشتیبان.
3. ریشه: آپلود مجدد ۱۶ فایل دانلودشدهٔ فاز ۰.
4. دوباره LiteSpeed Purge All.
