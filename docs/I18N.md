# Internationalization (i18n) — Layer B

> Phased multilingual design for the Knowledge Platform. No automatic bulk translation. Aligned with Agent.md addendum §14. Layer A already ships 9 locales (file-per-locale, manual).

## 1. Language priority (phased)
1. **Persian (fa)** — primary business language (matches the Persian blog).
2. **English (en)** — international/LLM-citation reach.
3. Strategic languages: **Arabic (ar)**, **German (de)**, **French (fr)**, **Turkish (tr)** (existing Layer A locales — reuse hreflang groups).
4. Remaining: Spanish (es), Chinese (zh-Hans), Japanese (ja).

## 2. Translation-group model (ontology §5)
- Each entity has a canonical source language + `kbk_translation_group` ID.
- Translations share the group ID; hreflang is generated from the group.
- `kbk_language` meta + a `?lang=` / path strategy (decided per Phase 9.3 below).

## 3. URL strategy (additive, no Layer A change)
- Layer B entity translations: `/entity/{slug}/?lang=fa` OR `/fa/entity/{slug}/` (decided at implementation; default `?lang=` to avoid new rewrite rules colliding with Layer A `/fa/` page slug).
- Each translation has its own title/description/hreflang/canonical; `x-default` → canonical source.
- Layer A locale slugs (`/fa/`, `/ar/`, …) remain the theme CV pages — **untouched**.

## 4. Translation rules (what must be preserved)
entity identity · technical meaning · citations · dates · product/org names · canonical relationships · translation-group IDs. Brand names (KSF, Padyar) not translated. URLs translated deliberately, not blindly.

## 5. Quality gates (no thin MT)
- No raw machine translation published at scale.
- Each translation: `editorial_status=draft` → human review → `published`.
- Glossary technical terms reviewed for terminology consistency before publish.
- `hreflang` validated symmetric within a group (Phase 12 test).

## 6. Implementation status
- ✅ Model supports i18n: `kbk_language`, `kbk_translation_group`, `kbk_schema_type`, `inLanguage` in JSON-LD.
- ⏳ Translation UI, hreflang emitter, slug policy — Phase 9 build (after MVP hub validation).

## 7. Anti-patterns
- No indexable thin translations.
- No duplicate-content translations without canonical/hreflang differentiation.
- No date bumping on translation publication (separate `translation_date`).
