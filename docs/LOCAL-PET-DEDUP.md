# مراحل محلی ۱ و ۲: بررسی تحویل و رفع دانلود تکراری Pet

## مرحلهٔ ۱

گزارش HANDOVER-STATUS و پشتیبان پایدار Antigravity بررسی شد. گزارش آن رفع دانلود تکراری را شروع‌نشده ثبت کرده بود. تغییرات موجود حفظ شدند؛ تست کامل قبل و بعد از اصلاح با exit code صفر عبور کرد. هیچ reset، commit، push یا انتشار انجام نشد.

## مرحلهٔ ۲

علت اول: preload افزونه URL نسخه‌دار داشت اما CSS background و Image runtime آدرس بدون نسخه می‌گرفتند. تنظیم server-side اکنون atlasUrl را می‌فرستد و هر دو مصرف‌کننده همان URL را می‌گیرند.

علت دوم: جلوگیری از اجرای Pet قدیمی، مانع دانلود تگ‌های hardcoded قالب و lazy loader نبود. سازندهٔ قالب اکنون تگ‌های اصلی JS/CSS قدیمی را فقط در نبود افزونه یا غیرفعال بودنش چاپ می‌کند. lazy loader نیز guard موجود را پیش از دانلود بررسی می‌کند.

فیلترهای حذف منابع قدیمی افزونه نیز اکنون گزینهٔ enabled را رعایت می‌کنند تا در حالت غیرفعال، Pet قالب مسدود نشود. حرکت، چت و تنظیمات Live Avatar تغییر نکردند؛ Live Avatar فعال نشد.

## شواهد

- npm test: exit 0 قبل و بعد از اصلاح.
- آزمون‌های wp-links: ده آزمون موفق، شامل دو رگرسیون جدید.
- رگرسیون DOM: اجرای دوبارهٔ فایل افزونه فقط یک Pet می‌سازد؛ background و Image یک atlasUrl نسخه‌دار دارند؛ API setMood باقی است.
- رگرسیون PHP: منابع قدیمی در حالت افزونهٔ فعال چاپ نمی‌شوند و در حالت غیرفعال باقی می‌مانند.
- sync dry-run: صفر اختلاف روی ۱۷ قالب و ۴۹۷ asset.
- PHP/JS syntax و git diff --check موفق.
- release prepare: ۱۶ فایل ریشه و قالب آماده؛ ZIP افزونه جدا بررسی شد.

محدودیت: این نوبت تست بصری مرورگر و اندازه‌گیری واقعی Network در WordPress اجرا نشد. تست‌های DOM/PHP محلی جایگزین ادعای سنجش سرعت production نیستند. آزمون shell قبلی ۳۲/۰ مربوط به مرحلهٔ ادغام است و در این نوبت تکرار نشده است.
