# قالب وردپرس KohandezhCV — نسخه 1.2.0

قالب اختصاصی kohandezh.com: رزومه و پورتفولیوی ۹‌زبانه، بلاگ native وردپرس، صفحات Certificates و PSN، و دستیار تعاملی CV.

نسخه 1.2.0 دستیار قابل‌جابه‌جایی CV، Tech Stack برندمحور، کنترل زبان مربعی و مسیریابی زبان بر پایه کشور IP را اضافه می‌کند. انتخاب دستی زبان در localStorage همیشه اولویت دارد؛ درخواست کشور IP فقط در نخستین ورود به صفحه اصلی انگلیسی ارسال می‌شود و در صورت خطا، فارسی پیش‌فرض است.

## پیش‌نیاز

- WordPress 6.0 یا جدیدتر؛ سازگاری قالب تا شاخه WordPress 7.0 ثبت شده است.
- PHP 7.4 حداقل فنی قالب است؛ برای سرور production از PHP 8.3 یا جدیدتر استفاده کنید.
- قبل از نصب یا به‌روزرسانی، از فایل‌ها و دیتابیس بکاپ کامل بگیرید.

## نصب و به‌روزرسانی

1. پیشخوان → نمایش → پوسته‌ها → افزودن → بارگذاری پوسته.
2. فایل `kohandezhcv.zip` را انتخاب و نصب/جایگزین کنید.
3. قالب را فعال کنید. در آپدیت‌های بعدی، migration نسخه‌دار قالب به‌صورت idempotent اجرا می‌شود.
4. تنظیمات → پیوندهای یکتا را باز کنید و در صورت نیاز یک‌بار ذخیره بزنید.

قالب صفحات `home`, `fa`, `ar`, `de`, `es`, `fr`, `tr`, `zh`, `ja`, `psn`, `certificates` و `blog` را، فقط در صورت نبودن، ایجاد می‌کند. صفحه Home به‌عنوان صفحه اول و Blog به‌عنوان صفحه نوشته‌ها تنظیم می‌شود.

## منبع اصلی و همگام‌سازی

پوشه `kohandezh.com/` منبع اصلی (single source of truth) است. فایل‌های `front-page.php` و `page-*.php` تولیدی هستند و نباید دستی ویرایش شوند؛ sync بعدی تغییر دستی آن‌ها را بازنویسی می‌کند.

بعد از هر تغییر در نسخه static اجرا کنید:

```bash
python3 wp-theme/sync-from-static.py
```

این دستور assets و همه templateهای تولیدی را sync می‌کند، invariantها را بررسی می‌کند و ZIP جدید می‌سازد. فایل‌های native وردپرس مانند `functions.php`, `home.php`, `single.php` و `index.php` دستی نگهداری می‌شوند.

## مدیریت محتوا

- نوشته‌های بلاگ و تصاویر شاخص از پیشخوان وردپرس مدیریت می‌شوند.
- پیش‌نمایش بلاگ با `WP_Query` از نوشته‌های واقعی دیتابیس ساخته می‌شود و به IDهای hardcode وابسته نیست.
- صفحات رزومه از static source تولید می‌شوند؛ متن یا layout آن‌ها را در `kohandezh.com/*.html` و assetهای همان پوشه ویرایش کنید.
- افزونه Polylang/WPML لازم نیست؛ زبان‌ها صفحات مستقل‌اند.

## WordPress Core

Core داخل بسته قالب نیست. به‌روزرسانی WordPress باید روی نصب واقعی production، پس از بکاپ و smoke test در staging، از مسیر پیشخوان → به‌روزرسانی‌ها یا ابزار مدیریت host انجام شود. پوشه archive این repository منبع production نیست و نباید به‌عنوان Core فعال ارتقا داده شود.
