# Kohandezh Book Bundle Format v1 (frozen)

| | |
|---|---|
| Format id | `kohandezh-book-bundle/1` |
| Frozen | 2026-10-02 |
| Reference bundle | `Books/ai-governance/` (code `AI`, edition `2026E1`, 7 parts / 53 chapters / 479 sections) |
| Validator | `python3 _tooling/ai-book/validate_book.py --root <dir>` |
| Packager | `python3 _tooling/ai-book/build_data_zip.py --slug <slug>` |
| Reader | WordPress plugin `kohandezh-knowledge` (`_tooling/wp-theme/kohandezh-knowledge/`) |

## 1. Purpose and freeze rule

- A book on kohandezh.com = **one folder in this format + one registry row**. Nothing else.
- The reader code is never edited for a particular book. A bundle that passes the validator renders exactly like the reference book.
- `master/book.json` is canonical and signed. Presentation fixes go in `master/reader-overlay.json`, never into `book.json` (§5).
- Any change to a rule in this file is a new format version (§12).

## 2. Directory layout

Paths are relative to the book root (`Books/<slug>/` in the repo, `Books/<Folder>/` on the server).

| `provenance/citation-registry.json` | required | repository, cite box | citation per structural ID |
| `provenance/release-manifest.json` | required | PDF view, verify | signed release facts; sha256/bytes of every artifact |
| `release/06_book_fa.pdf` | build | PDF view / download | printed edition |
| `release/09_glossary.json` | required | glossary view, search | approved terms |
| `release/14_rag_corpus_fa.jsonl` | required | ask view | retrieval chunks |
| `knowledge/graph.json` | required | graph view | entity graph |
| `knowledge/entities.jsonl` | required | concepts view, catalog | public entity list |

| `taxonomy/doc_titles_fa.json` | optional | sources view, chapter labels | Persian titles of source documents |
| `templates/TPL-*.json` | required (≥ 1) | templates view | worksheet cards |

- **build** = generated by the pipeline and gitignored in the repo (`Books/**/*.pdf`, `Books/ai-governance/html/`); required in every upload. The validator warns when they are absent, and fails under `--release`/`--strict`.
- Everything else in a book folder (pipeline sources, `config/`, `tools/`, translation memory, DOCX, CSV) is ignored by the reader and is not uploaded.
- All JSON is UTF-8, no BOM. `*.jsonl` = one JSON object per line.

## 3. `master/book.json`

Use: **D** = displayed by the reader, **P** = provenance (kept, verified, not displayed), **I** = integrity (hashed or cross-checked).

## 4. IDs and hashing

| ID | Grammar | Example |
|---|---|---|
| structural | `KDJ-{CODE}-{EDITION}-P{pp}-C{cc}-S{ss}` | `KDJ-AI-2026E1-P01-C01-S01` |
| content | `{structural}-{HASH8}` | `KDJ-AI-2026E1-P01-C01-S01-6FC077B0` |
| citation | = structural | |
| `CODE` | `[A-Z0-9]{1,8}`, one per book, never reused | `AI` = ai-governance |
| `EDITION` | `\d{4}E\d+` | `2026E1` |
| `pp`/`cc`/`ss` | two digits, zero-padded, from 01; max 99 per level (chapters: per book) | |
| `HASH8` | first 8 hex of `content_hash`, **uppercase** | |

**kdj-hash-1** (source of truth: `Books/ai-governance/config/provenance.yaml`, `tools/master.py`, `tools/verify_release.py`; the plugin never re-hashes):

```
content_hash = "sha256:" + hex( sha256( UTF-8(
    structural_id + "\n" + locale + "\n" + origin + "\n" +
    C(title_fa) + "\n" + C(title_en) + "\n" + C(fa_text) )))
C(s): NFC → CRLF/CR to LF → delete U+200B U+200D U+FEFF U+2060 U+200E U+200F
      U+202A–U+202E U+2066–U+2069 (ZWNJ U+200C is KEPT) → per line: runs of
      space/tab/U+00A0 → one space, rstrip → 3+ newlines → 2 → strip leading/trailing newlines
```

HASH8 is therefore **not** a hash of `fa_text` alone: the ID, locale, origin and both titles are hashed with it.

**Merkle** (bytes = raw 32-byte digests): leaf = `sha256(0x00‖h)`, node = `sha256(0x01‖L‖R)`, an unpaired node is promoted unchanged. `chapter_hash` = root over its sections' `content_hash`; `part_hash` = root over its chapters' roots; `merkle_root` = root over the parts' roots = `release-manifest.merkle_root`.

**Editing canonical text breaks:**

| Changed | Breaks |
|---|---|
| any hashed field of one section | its `content_hash` and `content_id` → `content_ids.json`, citation registry, `source_map`, search index, RAG chunk ids, graph/entity `mentions` |
| any byte of `book.json` | `chapter_hash`/`part_hash`/`merkle_root` (if hashed text), `release-manifest.master_json_sha256`, artifact `04_book_master_fa.json`, the Ed25519 manifest signature, `reader-overlay.book_sha256` (whole overlay silently dropped) |

→ Presentation fix: overlay (§5). Text correction: a **new edition** (`2026E2`), full pipeline re-run, new IDs, new signature.

## 5. Reader overlay — `master/reader-overlay.json`

| Key | Type | Rule |
|---|---|---|
| `schema` | string | `"kbk-reader-overlay/1"` |
| `edition_id` | string | = `book.edition_id` |
| `book_sha256` | string | sha256 of the exact `book.json` bytes on disk |
| `generator` | string | tool that wrote it (e.g. `tools/reader_overlay.py`) |
| `chapters` | object | `{"Cnn": {"title_fa": "…"}}` — only `title_fa` |
| `sections` | object | `{"<structural_id>": {"title_fa"?: "…", "fa_text"?: "…", "omit"?: true}}` |

- Applied only if `schema`, `edition_id` **and** `book_sha256` all match; otherwise the whole overlay is ignored and canonical text is shown (fail closed, never fatal). The validator FAILs a stale overlay.
- Replaces display text only. IDs, hashes, citations, search, RAG and verification keep the canonical text.
- `omit: true` hides a section (source-PDF debris); it weighs 0 in pagination.
- Generated, never hand-edited: for ai-governance `python3 Books/ai-governance/tools/reader_overlay.py` (write) / `--check` (stale → exit 1, run by `npm run test:ai-book`) / `--report`. A new book ships its own generator or none.
- **Footnotes:** a reference is `[^n]` (n = 1–4 digits, Latin or Persian; `[^9,10]` allowed); its definition is a line `[^n]: text` anywhere in the same section. Every reference must have a definition (a reference without one is dropped by the reader; the validator warns). Legacy packed definitions `[^]: > 1 text > 2 text` are still read.
- **Figures:** a `[FIGURE …]` marker on its own line becomes «تصویر · صفحهٔ N در نسخهٔ PDF» plus a caption when the marker matches a `figures[]` entry (`figure_id`/`id`/`ref`/`marker`; caption from `caption_fa`/`title_fa`/`caption`/`title`; page from `page`/`pdf_page`/`source_page`) or carries caption text after it; a bare marker is hidden. A marker inside running text or a table cell is dropped.

## 6. Supported Markdown (section `fa_text`, overlay `fa_text`)

| Construct | Syntax | Renders as |
|---|---|---|
| paragraph | lines separated by a blank line | `<p dir="auto">`; single newlines join with a space |
| heading | `#`…`######` + space | relative: the shallowest level in the section → h3 (section title is h2), next → h4…h6; never skips a level; id `{structural_id}-h{n}` |
| unordered list | `- item` / `* item` | `<ul>` |
| ordered list | `1. item` / `1) item` (Latin or Persian digits; `- 3. item` too) | `<ol>` keeping the number |
| blockquote | `> text` | one `<blockquote>` per line |
| table | consecutive lines `\| a \| b \|`; optional separator `\|---\|---\|` (≥ 3 dashes, `:` allowed) as 2nd row = header | see §8; `\|` inside a cell = literal pipe; short rows padded |
| bold / italic / code | `**b**` / `*i*` / `` `c` `` | `<strong>` / `<em>` / `<code>` |
| footnote | `[^n]` + `[^n]: text` | superscript link + per-page note list (§5) |
| link | `[text](https://…)` (http/https only) | `<a rel="noopener noreferrer" target="_blank">`; any other scheme stays literal |
| figure | `[FIGURE …]` | figure note or hidden (§5) |
| Latin runs | automatic | isolated `dir="ltr"` spans |

Not supported (shown literally, escaped or flattened — do not use): images `![a](u)`, non-http link schemes, raw HTML, `_emphasis_`, `~~strike~~`, code fences, setext headings, `#######`, nested lists (indent ignored), multi-line blockquotes, HTML entities. Tables must be rectangular (the validator warns on ragged ones).

## 8. Reader guarantees (what "same format" means)

Every bundle that passes gets exactly this presentation; none of it is configured per book.

| Feature | Behaviour |
|---|---|
| Reading order | parts → chapters → sections as in `book.json`; omitted (overlay) sections hidden |
| Pagination | per chapter; budget 30,000 characters per page (admin range 8,000–150,000, Settings → کتاب‌خوان); each section adds 1,000; pages pack whole sections; a section over budget is cut at its own headings (top level first), then between blank-line blocks; tables, lists and blockquotes are never split |
| Headings | section title h2; body headings relative h3–h6 (§6) |
| Tables | header + 2–5 columns → stacked cards on mobile with `data-label`; headerless 2–3 columns → cards titled by the first cell; wider → horizontal scroll |
| Footnotes | numbered list «پانوشت‌ها» closing each rendered page part, first-reference order, back-links |
| Digits | UI numbers (pages, counts, footnote marks, «بخش ۵، فصل ۳۸») in Persian digits; prose, IDs, hashes untouched |
| Bidi | Latin runs isolated so parentheses and codes stay in place |
| Cite box | per section: citation (`citation_fa`), content ID, direct link + copy |
| Navigation | chapter TOC with page markers, prev/next chapter, pager, related links, concept links |
| Progress | reading progress bar; resume-where-you-left-off (local to the browser) |
| Views | read, search, glossary, sources, templates, concepts, graph, ask, pdf, request-pdf, news |
| Print | print stylesheet for the reading view |
| Verification | `/ai-book/verify/` resolves any content/structural ID against `content_ids.json` and the release manifest |

## 10. Upload flow

1. Produce the bundle in `Books/<slug>/` (book pipeline; regenerate the overlay if there is one).
2. Validate: `python3 _tooling/ai-book/validate_book.py --root Books/<slug> --slug <slug> --release` → exit 0.
3. Package: `python3 _tooling/ai-book/build_data_zip.py --slug <slug>` → `_tooling/wp-theme/<slug>-data.zip`, one top folder `<SlugInCamelCase>/` (ai-governance: `ai-book-data.zip` / `AiBook/`). It re-validates and writes nothing on a FAIL.
4. Prove the extracted copy: `KBK_AI_BOOK_ROOT=<extracted folder> npm run test:ai-book`.
5. Upload and extract into the server's `Books/` → `Books/<Folder>/`.
6. Add the registry row (§9) and the two cover images.
7. Purge LiteSpeed Cache and Cloudflare for `/books/` and `/fa/books/<slug>/*`.

## 11. Validation

```
python3 _tooling/ai-book/validate_book.py [--root DIR] [--slug SLUG] [--code CODE] [--release] [--strict] [--json]
```

| Exit | Meaning |
|---|---|
| 0 | every check PASS, WARN or SKIP |
| 1 | at least one FAIL — do not upload |
| 2 | usage error (bad flag, root not a directory) |

| Mode | Absent build output (PDF, search index) | Absent optional file |
|---|---|---|
| default | WARN | SKIP its check |
| `--release` | FAIL | SKIP its check |
| `--strict` | FAIL | FAIL |

Checks: `files`, `book.top_level`, `book.structure`, `book.section_fields`, `ids.grammar`, `ids.content_hash`, `ids.merkle`, `provenance.content_ids`, `provenance.citations`, `edition.consistency`, `provenance.release_manifest`, `overlay`, `markdown.tables`, `markdown.footnotes`, `markdown.figures`, `markdown.unsupported`, `taxonomy.doc_titles`, `release.glossary`, `manifests.sources+bibliography`, `master.source_map`, `templates`, `knowledge.graph`, `knowledge.entities`, `release.rag_corpus`, `html.search_index`, `pdf.file`. Markdown checks run on the text the reader shows (overlay applied when it matches). FAIL = the contract or the reader's own validation is broken; WARN = renders, but loses or misplaces something (ragged table, footnote without definition, literal link, duplicate chapter slug, `book.json` not byte-identical to the signed master).

`npm run test:ai-book` runs the validator on `${KBK_AI_BOOK_ROOT:-Books/ai-governance}`.

## 12. Versioning

| String | Where | Current |
|---|---|---|
| bundle format | this file, `validate_book.FORMAT` | `kohandezh-book-bundle/1` |
| overlay schema | `reader-overlay.schema` | `kbk-reader-overlay/1` |
| hash spec | `book.hash_spec`, `release-manifest.hash_spec` | `kdj-hash-1` |
| book edition | `edition_id` | `YYYYE#` per book |

- **Compatible (stays v1):** new optional keys or files; more parts/chapters/sections within the limits; new glossary terms, entities, templates; a new edition of a book.
- **Breaking (v2 + a plugin release first):** removing, renaming or retyping a required key; changing a required path, the ID grammar, kdj-hash-1, the Merkle construction, the overlay schema or its apply rule, the Markdown semantics in §6, the URL shapes in §3/§9, the chapter numbering rule.
- A book's text changes only by a new edition; its presentation changes only by its overlay.
