## Critical conventions (do not violate)

1. **Never edit `*.min.{js,css}` directly.** Edit the unminified source, then run `./build.sh`.
2. **Never edit `_tooling/wp-theme/kohandezhcv/*.php` templates** (front-page.php, page-fa.php, etc.). They are auto-generated. Edit the corresponding `*.html` at repo root, then run sync.
3. **`functions.php` is hand-maintained** — it is NOT regenerated by sync. Edit it directly.
4. **Cache-bust every `.min.{js,css}` change** by bumping `?v=N` in all 9 HTML files. Pattern: `?v=37 → ?v=38`.
5. **English canonical URL `/`** must stay indexable by bots. Never JS-redirect it to a non-English locale without a bot check. The locale-router v2 already handles this correctly.
6. **Asset URLs differ between static and WP:**
   - Static repo: `assets/css/styles.min.css`
   - Production WP: `wp-content/themes/kohandezhcv/assets/css/styles.min.css`
   - This is handled by the sync script — don't manually rewrite paths.
7. **jQuery has been REMOVED — never re-add `jquery.min.js` or `jquery-validate.js`.**
   They are replaced by **`assets/js/jquery.shim.js`** (→ `jquery.shim.min.js`, ~14 KB), a
   hand-written compat shim implementing exactly the jQuery subset this site uses
   (selectors, traversal, classes, data, events, `$.ajax`, `.serialize`, plus a native
   `form.checkValidity()` replacement for the dropped validate library). All consumer
   files (`main.js`, `gsapAnimation.js`, `countto.js`, `carousel.js`,
   `animation-change-text.js`) run **unchanged**. If a script needs a jQuery method
   the shim doesn't have, **add the method to `jquery.shim.js`** — do NOT restore real
   jQuery. The jQuery originals were archived and then deleted on 2026-08-09; the shim is the only implementation.

## Deploy flow (after any change)

```bash
# 1. If you changed any JS/CSS source, regenerate .min files:
./build.sh

# 2. If you changed any HTML, sync to WP theme + rebuild zip:
python3 _tooling/wp-theme/sync-from-static.py

# 3. Upload _tooling/wp-theme/kohandezhcv.zip via:
#    wp-admin ← Appearance ← Themes ← Add New ← Upload Theme
```

The `kdcv_content_schema_version` in `functions.php` triggers automatic
migrations (page creation, rewrite flush, duplicate cleanup) on next
wp-admin visit. **Bump it whenever you add new admin_init work.**

## Known gotchas

1. **dev-server.php serves on http://127.0.0.1:8735** — PHP built-in, doesn't have prod's URL rewriting. Asset URLs that work on prod may 404 locally. Test critically on staging or prod after deploy.
2. **The static `sitemap.xml` references `/PSN.html` and `/Certificates.html`** which don't exist on WP prod (they're `/psn/` and `/certificates/` there). This is intentional — the legacy redirect in functions.php catches these. Static deploy keeps the .html URLs.
3. **The avatar (avatar-professional.webp) is loaded eager with fetchpriority="high".** Do not lazy-load it.
4. **`locale-router.min.js` must be render-blocking** (NOT defer/async). It needs to run before any other JS so it can redirect ASAP. All other scripts are deferred.
5. **`build.sh` regenerates ALL .min files**, not just the one you edited. Always bump all `?v=N` after running it (or use the Perl one-liner in WORK-LOG.md). NOTE: `jquery.shim.min.js` is built with `terser` directly (not via build.sh) — see how it was last minified before changing the command.
6. **Cloudflare's `HTTP_CF_IPCOUNTRY` header** is auto-detected by the geo-router. If CF is added in front later, no code change is needed — it'll skip the ip-api.com call entirely.
7. **Do NOT re-encode `assets/media/phase11-award.mp4`** (the blog version, ~6.1MB). It is already optimally compressed; a CRF-26 re-encode *bloats* it to ~9MB. The other 3 media files (`phase-11-award.mp4`, `mohammad-kohandezh-interview.mp4`, `inspiring.mp3`) DO benefit from re-encode. Pre-encode originals were deleted on 2026-08-09 — the re-encoded files are now the only copies.
8. **The jQuery shim is API-compatible but NOT a full jQuery.** It implements exactly the methods this site's 7 consumer files use (verified). When adding a new script that uses jQuery, check its methods exist on `jQuery.fn` in `jquery.shim.js` — add any missing ones there rather than reaching for real jQuery. Test in real Chrome (jsdom lacks `matchMedia`/`fetch`/SVG-geometry and gives false errors).
10. **Three page stylesheets used to be hard-coded dark; all are theme-aware now.**
    `blog.css`, `psn.css`, `certificates.css` key their light skin off
    `html[data-kdcv-theme="light"]` — the ATTRIBUTE, not `body.dark-mode`, because
    `<html>` itself is painted on those pages. The attribute is set pre-paint by the
    theme-boot inline script in each page head and kept in sync by page-chrome.js.
    When adding a colour to one of these files, add a token, not a literal.
11. **Accent colours come in pairs: a SURFACE and an INK.** `--primary` / `#a8ff46` /
    `#d5ff3f` work as a filled pill with dark text on top, and fail as text on a light
    page (measured 1.3–1.9:1). Every palette now carries a second token
    (`--b-accent-ink`, `--psn-primary-ink`, `--certificate-primary-text`) for the
    text case. Use the ink token whenever the accent is `color:`, never `background:`.
12. **Never write `a { color: inherit }` at (0,1,1) specificity.** `.psn-page a` was
    beating `.psn-button--primary`, rendering the CTA white-on-green at 1.73:1. Anchor
    resets are written as `.page :where(a)` so they contribute zero specificity.
13. **`read_console_messages` accumulates across navigations and does NOT report the
    source file.** For load-time errors run the dev server with `KDCV_DEV_TRACE=1`; it
    injects a capture-phase error recorder into every HTML response and
    `window.__KDCV_ERRS` then gives filename/line/column. That is how the long-standing
    "unattributed SyntaxError" was finally traced to `this.media=047all047`.
14. **CSP is ENFORCED** in `.htaccess`, in `functions.php` (front end only — wp-admin
    is excluded) and mirrored by `dev-server.php` so it is exercised locally. Adding
    any external resource, `eval`, a Worker or a blob URL requires updating all three.
15. **The Web3Forms key is NOT in the WordPress templates.** It lives in the
    `kdcv_contact_access_key` option and is used only by `POST
    /wp-json/kohandezh/v1/contact`. `sync-from-static.py` strips the hidden input and
    FAILS the build if one survives. The static files keep their key — no server there.

16. **Images: AVIF + WebP, no JPEG/PNG fallback tier.** `<picture>` blocks are
    `<source type="image/avif">` + `<img src="X.webp">`. Do NOT add a
    `<source type="image/webp">` — the `<img>` already is one. JPEG/PNG survives
    only where the format is required: `og:image` / `twitter:image`, schema
    `"image"`, favicons, the PWA manifest icon, and the blog-import `.wxr`.
    Pre-conversion JPG/PNG originals were deleted on 2026-08-09 — WebP/AVIF are the only copies.
17. **WebP is not automatically smaller.** Encode lossy AND lossless, keep the
    smaller, and skip the file if neither beats the source — two already-tight
    JPEGs grew. `logo.png` went 227 KB -> 5 KB; other files barely moved.
18. **Renaming an image? Mind the suffix collision.** `logo.png` is a suffix of
    `footer-logo.png`. Any scripted rewrite needs `(?<![A-Za-z0-9._-])` before
    the basename or it corrupts the longer name.
19. **Measure contrast with animations at rest.** Force
    `*{opacity:1!important;animation:none!important}` before auditing. The entry
    animations multiply into the opacity chain and give both false passes and
    false failures — the hero accent's real 1.67:1 hid behind one for several
    passes.
20. **`.text-black-*` utilities are `!important`** in bootstrap.min.css AND
    styles.css. Overriding one needs `!important` too; specificity alone loses.
21. **The service worker caches `?v=` URLs cache-first and never revalidates.**
    That is safe only if a changed file always gets a changed version. Rebuilding
    without bumping (normal during development) poisons the cache. Bump
    `CACHE_VERSION` in sw.js on any deploy that changes many assets — the
    activate handler is what evicts the old cache.

22. **Typography is Inter (copy) + Apfel Grotezk (display), site-wide.** Apfel
    Grotezk is defined in `assets/fonts/fonts.css`, so ANY page using it must
    link that file — `/portfolio/` did not, and setting the family without it
    silently falls back to Inter. RTL keeps its own faces: Estedad for Persian,
    InkBrushArabic for Arabic headings. **Do not introduce another Latin face.**
    `CassandraPersonalUseRegular.ttf` was removed on 2026-08-09 (personal-use
    licence on a commercial site, and it was set on `body`); the .ttf was deleted on 2026-08-09; the reasoning is in WORK-LOG.md.

23. **`kdcv-interaction-fix.js` uses capture-phase `stopImmediatePropagation()`
    on the sidebar links.** It is generated, so it cannot be edited — and it
    silently kills any OTHER click listener on those elements. Never add
    behaviour there via `addEventListener('click')`; watch the `class`
    attribute with a MutationObserver instead (see `limelight-nav.js`).
24. **The chat panel is positioned by the host bundle's inline `top` but sized
    by chat-ui.css.** Those two must be reconciled or the panel hangs off the
    bottom — `keepPanelOnScreen()` in chat-ui.js does it. Note `style.top` and
    the painted rect differ by the panel's open transform (~31px); convert
    between them or every correction lands short by that amount.
25. **The chat panel is `overflow: hidden`.** Any popup inside it (the language
    menu) must open INWARD — `inset-inline-start`, not `inset-inline-end` — or
    it gets clipped. Three languages were invisible this way.
26. **Cleanup: match on basename AND bare stem.** `resume-timeline.js` builds
    `"assets/images/employment/" + slug + ".webp"`, so a basename-only
    reference check reports all 8 employment logos as dead. The cleanup of 2026-08-09 was archived and then permanently deleted at the
    owner's request — nothing is recoverable from disk, so re-verify before
    removing anything else.

27. **`siteLang` records the visitor's CHOICE, never a page's authored
    language.** It is written only by the CV pages (whose URL *is* the language)
    and by an explicit `?lang=`. Writing it from e.g. Certificates — authored
    `lang="en"` — overwrites a Persian visitor's choice with English.
28. **`<html data-kdcv-i18n="in-place">` marks pages that translate live**
    (Certificates, portfolio). Only those follow `?lang=`/`siteLang`; every
    other page keeps its authored language so the chrome never ends up in a
    different language from the body. Add the attribute if you make another
    page translatable.
29. **`Certificates.html` has an inline `<head>` bootstrap that hard-sets
    `documentElement.lang` and the hero copy.** It runs before every module and
    wins. Any change to how the locale is chosen must be made THERE as well as
    in `certificates-i18n.js`, or the two will disagree.
30. **The chat language follows the page language.** A manual pick is scoped to
    the page language it was made on (`kdcvChatLangFor`), so it cannot leak onto
    a differently-languaged page.
31. **Default locale is `fa` when there is NO signal** — in both
    `locale-router.js` (`DEFAULT_LOCALE`) and the functions.php geo router. A
    real `en` signal still keeps English. Both defaults sit AFTER the bot check,
    which is what keeps `/` the English canonical for crawlers (convention #5).
    Do not move either default above its bot guard.

9. **TTS / voice-clone API keys live in WordPress, never in the browser.** The `kohan-avatar` plugin has **Settings → Kohan Avatar → Voice & TTS Services** (provider / endpoint / API key / voice). The key is stored server-side (`kohan_avatar_tts` option) and only ever used by the `kohan-avatar/v1/tts` REST proxy route. The browser receives only `window.KDCV_VOICE = {provider, configured, endpoint, voice}` (no key) via a `wp_footer` inline script. If no server voice is configured, `wisdom-quotes.js` and the avatar fall back to the Web Speech API (fa-IR). To add a Whisper voice clone: paste the key in that settings page — never hardcode it in JS.

32. **A panel that is dark in BOTH themes must say so, not be inverted.**
    `.section-blog` ("Field notes") paints a hard-coded dark gradient with no
    light-mode variant, and its FIELD NOTES watermark is a light ink. A pass
    that inverted the copy for light mode on the assumption the panel goes
    light produced 1.14–1.23:1 — worse than the bug it fixed. Before writing a
    `body:not(.dark-mode)` ink rule, check whether the SURFACE actually
    changes. `.wg-work .work-localized-*` is the pattern to copy.
33. **`.language-button-label` lives under `.btn-setting-color`, not
    `.tf-left-bar`.** The pre-existing `.tf-left-bar .language-button-label`
    rule matches nothing on the CV pages, which is how the chip ended up
    inheriting `rgba(255,255,255,.4)` into light mode (1.04:1 — invisible).
    When a colour bug survives an obvious-looking rule, check the rule matches.
34. **AVIF is not automatically smaller than WebP either** (the sibling of
    gotcha 17). All 27 certificate AVIFs were LARGER than their WebP twins, so
    the `<picture>` blocks there correctly ship no AVIF `<source>` and the
    files were dead weight (2.47 MB, deleted 2026-08-18). Before adding an
    AVIF `<source>`, compare the two files; keep the smaller one.
35. **`.icon-arrow-right-top` reusing `arrow-up.svg` is deliberate**, not a
    duplicate asset: it is the same mask rotated 45°. An audit that compares
    mask URLs will flag it — do not "de-duplicate" it.
36. **The generated `kdcv-resume-entry-fix.js` has carried a Shamsi start date
    a year ahead of the current one**, which rendered as "2027 – Present" — a
    role that has not begun but is also current. `timeline-date-fix.js` now
    drops the year and shows only the locale's word for "now" when a converted
    start lands in the future. If the real start date is known, fix it at the
    source instead; the guard is a floor, not an answer.
37. **`_tooling/wp-root/` is a hand-kept mirror with rewritten paths, and it
    goes stale silently.** `sw.js` sat at `CACHE_VERSION = "v4"` while the root
    was at v7, `sitemap.xml` was missing 4 URLs and `offline.html` pinned
    `?v=41` assets. Nothing syncs it — diff all five files against the root
    copies whenever either side changes. Only the `/wp-content/themes/…` path
    prefixes and manifest formatting are meant to differ.

38. **On WordPress the AVATAR IS THE PLUGIN'S, not the theme's.** `kohan-avatar`
    mounts `.kohan-avatar-root` and sets `window.__KDCV_PET_BOOTSTRAPPED__`, so
    the theme's `ai-pet.js` never builds `.kdcv-pet-root` — that selector matches
    nothing in production while matching fine on the static dev server. Any
    avatar-adjacent script must name BOTH roots. `kohan-avatar-enhance.js` named
    only the theme root, so `boot()` retried forever, the double-click tween and
    the arrow-key loop never bound, and `data-kohan-walking` was never written —
    which is the one attribute `kohan-drive.js` watches, so the McLaren was
    built, positioned, and then waited for a signal that could not arrive.
    Test avatar features against a real WP install, not only `dev-server.php`.
39. **The plugin ships its OWN copy of `assets/kohan/spritesheet.webp`.** It was a
    lower-quality re-encode of the same 1536x2288 8x11 atlas — 460 KB against the
    theme's 794 KB — with visible compression blocks around the face and hands.
    Because the plugin's avatar is the one that renders, that degraded copy was
    what every visitor saw. The two files must be kept identical; after changing
    `assets/kohan/`, copy it into `_tooling/wp-theme/kohan-avatar/assets/kohan/`
    and rebuild the plugin zip, or the theme's artwork never reaches anyone.
40. **A hidden browser tab does not advance CSS animations**, so
    `animation: ... both` reports its `from` keyframe forever. The drive-mode car
    read `opacity: 0` at every step of a correct state machine purely because of
    this. Suppress the animation (`el.style.animation = "none"`) and read the
    DECLARED value before concluding an element is invisible. Sibling of gotcha 19.

### `KDCV_PAGE_CONTEXT` schema

```js
{ url, type, lang, title, summary, topics: string[], published }
// type: cv | blog-post | blog-index | certificates | portfolio | psn | videos | legal | page
```

A page may set `window.KDCV_PAGE_CONTEXT` itself before the script loads; a
hand-written value always wins over the derived one.

### Button system

`.kdcv-btn` + `--sm/--md/--lg` and `--primary/--ghost/--accent`. Existing
families (`.tf-btn`, `.tf-btn-action`, `.btn-color`, `.demo-mode-btn`, …) are
unified onto the same radius/easing/focus/touch language without re-tagging
markup, so each keeps its own size and colour.

### Theme class gotcha

Dark mode is `body.dark-mode`; **light is the unclassed default**. There is no
`body.light` — rules written against it silently match nothing. Use
`body:not(.dark-mode)` for light-only styling.

### Touch targets

Floors are gated on **viewport width** as well as `pointer: coarse` — a narrow
window on a mouse device reports `pointer: fine` but still needs 44px targets.
